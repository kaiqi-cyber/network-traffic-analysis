# network-traffic-analysis

A beginner-friendly project to learn capturing my own network traffic analysis using Wireshark to identify what DNS, TCP and TLS look like on the wire.

## Overview

I captured traffic from a Kali Linux virtual machine while Firefox was running and while visited https://example.com. Then, I used display filters to separate the protocols and documented what each one shows.

## Lab Environment

| Item | Detail |
|---|---|
| Host | Windows PC running VMware Workstation |
| Guest OS | Kali Linux 2022.1 |
| Network mode | NAT |
| Capture interface | eth0 |
| Tool | Wireshark |
| Browser | Firefox |

The capture only contains traffic generated by my own VM, in my own lab.

## What I Did

1. Checked the VM's interface and connectivity using command "ip -br addr" and "ping -c 4 1.1.1.1".
2. Started a Wireshark capture on eth0.
3. Generated traffic by browsing to https://example.com.
4. Stopped the capture and applied the display filters dns, tcp and tls.
5. Inspected individual packets and recorded what I observed.

## Key Observations

- DNS: The VM sends DNS queries in plain text over UDP port 53 to the NAT gateway before connecting to a site, requesting both A (IPv4) and AAAA (IPv6) records.
- TCP: Each HTTPS connection starts with a three-way handshake (SYN, SYN-ACK, ACK) to port 443.
- TLS: After the handshake, a Client Hello and Server Hello are exchanged and the rest of the data appears as encrypted Application Data.
- The server name in the Client Hello was still readable in the packet bytes so even encrypted traffic reveals which service is being contacted.

## Privacy and Ethics

- I only captured traffic from my own virtual machine in my own lab.
- The raw .pcapng capture file is not published because it contains network metadata.
- Screenshots were cropped to remove personal information.
